# Internet deployment

This API is prepared for a Render Docker web service. It uses PostgreSQL for
users, sessions, and admin audit records, and MongoDB for event/telemetry logs.
Both databases must be reachable before the API starts; the current server
intentionally does not start in a partially configured mode.

## Required hosted services

- A PostgreSQL database, such as Neon. Set its PostgreSQL connection string in
  Render as `DATABASE_URL`, retaining the provider's TLS parameters.
- A MongoDB Atlas cluster. Create a database user and set the Atlas connection
  string in Render as `MONGODB_URI`.
- A Render web service for the API, backed by this repository's `render.yaml`.

Neon only supplies PostgreSQL; it does not replace MongoDB or host this Node API.

## Deploy sequence

1. Push this project to a **private** GitHub repository. There is currently no
   Git repository or remote configured in this project folder.
2. Create a Neon PostgreSQL project and copy its connection string. Keep its
   TLS query parameters (Neon connection strings include `sslmode=require`).
3. Create an Atlas cluster and database user. In Atlas Network Access, allow the
   outbound CIDR ranges shown for the Render service's region. Do not use
   `0.0.0.0/0` as a shortcut.
4. In Render, connect the private GitHub repository and create a Blueprint from
   `render.yaml`. Enter `DATABASE_URL` and `MONGODB_URI` in Render's secret
   environment variable prompts. `JWT_SECRET` is generated by Render.
5. After the service has a hostname, set `PUBLIC_ORIGINS` to the comma-separated
   origins of any separate browser frontend that will call this API. The API's
   own Render origin is allowed automatically from Render's `RENDER_EXTERNAL_URL`.
6. Wait for `/api/v1/health/ready` to return HTTP 200 with both database
   dependencies marked `up`. The first start runs the SQL migrations once.

Never put real database URLs, passwords, or JWT secrets in this repository or
in Postman collection files. Configure them in the hosting provider's secret
environment settings.

## Free-tier behavior

The Render Blueprint requests a free web instance for demonstration. Render
free services can sleep after inactivity, take about a minute to wake, and have
no persistent local filesystem. Durable data therefore belongs in the hosted
databases. For an always-on public service, choose a paid compute plan and
review both database providers' storage and usage limits.

The API is not deployed merely by adding this file. A Git provider connection,
the two database services, their credentials, and a successful cloud build are
still required before a real public URL can be issued.
